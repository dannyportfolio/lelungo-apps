# Paket Arsitektur Phase 0 Lelungo

> **Current implementation:** Lelungo masih berupa aplikasi Next.js travel-deal/affiliate yang berjalan, ditambah fondasi PMS parsial berupa tenancy, resolusi tenant, konteks server, staff membership, dan katalog RBAC awal. Authentication adapter, UI staf terlindungi, dan domain PMS lainnya belum diimplementasikan.
> **Target state:** Satu paket arsitektur modular-monolith yang menjadi dasar terkontrol untuk evolusi Lelungo menjadi PMS dan direct-booking marketplace tanpa menganggap microservice atau domain rencana sudah berjalan.
> **Decision status:** README ini adalah indeks kanonik Phase 0. Status keputusan teknis tetap mengikuti ADR terkait; proposal atau OpenSpec change aktif tidak sama dengan implementasi yang diterima.
> **Last verified:** 2026-08-09

## Tujuan dan batas paket

Direktori ini adalah permukaan review kanonik untuk Phase 0. Paket ini menyintesis bukti current state, keputusan, target architecture, strategi migrasi, dan readiness gate. Ia tidak mengubah runtime, schema, dependency, deployment, atau data.

Rincian faktual yang sering berubah tetap dimiliki oleh `docs/current-system/`; keputusan historis tetap dimiliki ADR; requirement normatif tetap dimiliki OpenSpec. Dokumen bernomor di sini menghubungkan dan merekonsiliasi sumber-sumber tersebut agar reviewer tidak perlu menebak mana fakta saat ini dan mana rancangan masa depan.

## Legenda status

Setiap dokumen paket memakai empat field berikut.

| Field                      | Arti                                                                                                                                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Current implementation** | Fakta yang terlihat pada source, schema, konfigurasi, test, atau automation repository per tanggal verifikasi. Detail rencana tidak boleh masuk sebagai kemampuan berjalan.                                                                            |
| **Target state**           | Keadaan yang diusulkan untuk fase mendatang. Entitas, tabel, API, event, worker, broker, cache, storage, atau service berlabel ini belum ada kecuali dinyatakan lain secara eksplisit.                                                                 |
| **Decision status**        | `Accepted` telah diputuskan dalam ADR; `Proposed` masih memerlukan review/acceptance; `Deferred` sengaja ditunda sampai fase pemiliknya; `Open` belum memiliki bukti atau keputusan cukup; `Superseded` hanya sah melalui catatan keputusan pengganti. |
| **Last verified**          | Tanggal terakhir klaim repository ditelusuri ke bukti. Tanggal bukan bukti bahwa deployment, database, atau layanan eksternal telah diverifikasi.                                                                                                      |

Label verifikasi tambahan yang dipakai bila perlu:

- `VERIFIED`: command atau pemeriksaan yang disebut benar-benar dijalankan dan hasilnya direkam.
- `OBSERVED`: dapat dibuktikan melalui file repository, tetapi tidak mengeksekusi integrasi eksternal.
- `BLOCKED`: pemeriksaan dicoba atau dipreflight, tetapi lingkungan/tooling menghalanginya.
- `UNKNOWN`: repository tidak menyediakan bukti yang cukup; tidak boleh dinaikkan menjadi `PASS`.

## Glossary inti

| Istilah                          | Definisi kanonik Phase 0                                                                                                                                                                                                                           | Status saat ini                                                                                  |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **Tenant / Organization**        | Batas bisnis dan isolasi data untuk satu operator akomodasi. `Tenant` adalah nama teknis pada fondasi Prisma saat ini; `Organization` adalah istilah produk target. Pergantian nama tidak boleh dilakukan tanpa migration plan.                    | `Tenant`, domain, dan membership parsial sudah dimodelkan.                                       |
| **Platform context**             | Request tanpa tenant authority yang hanya boleh menjalankan operasi global melalui autentikasi dan izin platform eksplisit. Bukan bypass tenant otomatis.                                                                                          | Bentuk context ada; authentication/platform authorization end-to-end belum ada.                  |
| **Tenant context**               | Context server tepercaya yang mengikat tenant hasil resolusi host, actor terverifikasi, membership aktif, permission, dan correlation ID.                                                                                                          | Resolusi tenant dan membership parsial ada; actor masih disuplai caller, bukan identity adapter. |
| **Property**                     | Tempat usaha/akomodasi yang dikelola Organization, misalnya villa, homestay, guesthouse, atau hotel kecil. Bukan sinonim untuk satu kamar.                                                                                                         | Target only.                                                                                     |
| **Accommodation classification** | Klasifikasi model jual/operasi, misalnya entire-property/private villa atau room-based homestay. Ia membentuk aturan inventory, bukan menggantikan Property.                                                                                       | Target only.                                                                                     |
| **Room Type**                    | Produk jual yang mengelompokkan kapasitas, fasilitas, dan aturan unit kompatibel, misalnya Deluxe atau Family.                                                                                                                                     | Target only.                                                                                     |
| **Physical Unit / Unit**         | Ruang atau akomodasi fisik individual yang dapat ditempati dan tidak boleh memiliki occupancy overlap yang tidak sah.                                                                                                                              | Target only.                                                                                     |
| **Inventory Pool**               | Kuantitas jual per tanggal untuk sekumpulan kapasitas kompatibel ketika unit fisik belum atau tidak dipilih pada saat booking.                                                                                                                     | Target only.                                                                                     |
| **Availability**                 | Hasil otoritatif dari inventory, hold, reservation, restriction, dan operational block; cache/UI bukan sumber kebenaran.                                                                                                                           | Target only.                                                                                     |
| **Reservation**                  | Aggregate komersial yang menyatakan intent dan komitmen pemesanan beserta item, harga snapshot, sumber, dan lifecycle. Gunakan istilah ini untuk domain target; kata “booking” pada kode lama atau permission saat ini adalah warisan terminologi. | Target only.                                                                                     |
| **Inventory Hold**               | Klaim sementara, ber-TTL, idempoten, dan transaksional atas inventory selama penyelesaian booking/payment.                                                                                                                                         | Target only.                                                                                     |
| **Guest**                        | Pihak yang memesan atau menginap; profilnya mengandung PII dan harus diekspos melalui DTO minimum-field.                                                                                                                                           | Target only.                                                                                     |
| **Stay**                         | Lifecycle operasional kedatangan, penempatan unit, check-in, occupancy, dan check-out. Tidak disatukan dengan state Reservation atau Housekeeping.                                                                                                 | Target only.                                                                                     |
| **Rate Plan**                    | Paket aturan komersial/cancellation/restriction yang memilih input pricing; bukan satu kolom `room.price`.                                                                                                                                         | Target only.                                                                                     |
| **Pricing Snapshot**             | Rekaman immutable dari currency, integer minor-unit amounts, line item, aturan/input version, tax, fee, discount, dan total yang menjelaskan harga reservation.                                                                                    | Target only.                                                                                     |
| **Payment**                      | Rekaman lifecycle transaksi tamu/provider seperti intent, authorization, capture, void, provider event, dan refund. Tidak identik dengan invoice, settlement, payout, atau subscription billing Lelungo.                                           | Target only.                                                                                     |
| **Finance**                      | Ownership guest invoice, ledger/posting seimbang, settlement allocation, operational platform/owner fee, dan payout. Finance mengonsumsi fakta Payment tanpa mengubah transaksi provider.                                                          | Target only.                                                                                     |
| **Staff Membership**             | Hubungan user eksternal dengan tenant/platform dan lifecycle keanggotaannya. Membership bukan bukti autentikasi.                                                                                                                                   | Diimplementasikan parsial dalam Prisma.                                                          |
| **Role / Permission**            | Role mengelompokkan permission; permission adalah capability stabil yang diperiksa bersama scope dan membership aktif. Nama role tidak boleh menjadi satu-satunya authorization check.                                                             | Katalog dan pure authorization check awal ada; provisioning/integrasi request belum lengkap.     |
| **Domain event**                 | Fakta masa lalu dari perubahan aggregate. Saat ini targetnya berupa event in-process/outbox-compatible; bukan klaim broker telah berjalan.                                                                                                         | Target only.                                                                                     |

## Aturan penggunaan paket

1. Sebelum implementasi, buka dokumen bernomor yang relevan, ADR terkait, OpenSpec spec, dan current-state evidence.
2. Jangan menyalin target entity/event/API menjadi kode hanya karena terdapat dalam paket; buat OpenSpec change implementasi tersendiri.
3. Jika source berubah, perbarui dokumen current-system dan audit sintetis yang terdampak pada change yang sama.
4. Jika keputusan berubah, buat ADR yang menyupersede keputusan lama dan perbarui cross-link; jangan menulis ulang sejarah diam-diam.
5. Jika pemeriksaan tidak tersedia, rekam sebagai `BLOCKED` atau `UNKNOWN`; jangan mengubahnya menjadi keberhasilan inferensial.
6. Readiness Phase 1 hanya berarti scope foundation yang direkomendasikan boleh dimulai. Itu tidak berarti PMS, deployment, atau keamanan produksi sudah siap.
