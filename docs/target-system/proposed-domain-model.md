# Proposed domain model

| Domain                               | State                                               | Ownership and notes                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------ | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tenant                               | Foundation implemented                              | Organization/isolation root                                                                                                                                                                                                                                                                                                         |
| User / Staff / Role / Permission     | Phase 2 foundation implemented; locally DB-verified | Provider-verified subject, active Tenant membership, same-Tenant Tenant-role assignment path, explicit permission, Property access mode/version, selected grants, and minimum-field scope administration exist. Registration, invitations, recovery, MFA, custom roles, and recognizable staff profiles remain deferred.            |
| Property                             | Phase 2 foundation implemented; locally DB-verified | Tenant-owned aggregate with normalized slug, canonical IANA timezone, structured Indonesian address, classification/amenities, optional safe public presentation fields, lifecycle, optimistic version, protected staff services/UI, and one allowlisted published-identity resolver. No public list or direct public route exists. |
| Room Type / Room                     | Planned                                             | Property-owned sellable inventory structure                                                                                                                                                                                                                                                                                         |
| Rate Plan / Availability / Inventory | Planned                                             | Availability and pricing rules; transaction-sensitive                                                                                                                                                                                                                                                                               |
| Reservation / Reservation Guest      | Planned                                             | Booking aggregate and participant link                                                                                                                                                                                                                                                                                              |
| Guest Profile                        | Planned                                             | Tenant-scoped PII with minimum-field reads                                                                                                                                                                                                                                                                                          |
| Stay / Check-in / Check-out          | Planned                                             | Operational lifecycle, separate from reservation state                                                                                                                                                                                                                                                                              |
| Payment / Invoice / Expense          | Planned                                             | Financial records and provider adapters                                                                                                                                                                                                                                                                                             |
| Housekeeping / Maintenance           | Planned                                             | Operational tasks and room impact                                                                                                                                                                                                                                                                                                   |
| Booking Channel / Direct Booking     | Planned                                             | External source adapters and public booking boundary                                                                                                                                                                                                                                                                                |
| Notification                         | Planned                                             | Outbox-driven delivery adapters                                                                                                                                                                                                                                                                                                     |
| Audit Log                            | Narrow Phase 2 write contract implemented           | Transactional append-only evidence for successful Property and membership Property-scope mutations with allowlisted changed-field metadata. General browsing, export, retention management, and later-domain evidence remain planned.                                                                                               |
| Report                               | Planned                                             | Tenant-scoped read models, not cross-module writes                                                                                                                                                                                                                                                                                  |

Every tenant-owned aggregate carries `tenant_id`. Cross-domain references use stable IDs and application services, not direct imports of repository internals. Guest identity and payment fields require explicit data classification before schema creation.

Five Phase 2 integration files passed 29/29 tests (`9 + 8 + 2 + 8 + 2`) against disposable PostgreSQL 16. Focused real tenant-host authentication and missing-permission Chromium scenarios also passed, but the complete seven-scenario Property E2E rerun has not completed. These local results do not imply staging, production, remote-CI, live-provider, or final migration-readiness evidence.
